{\small
\term{Overview.} I fine-tuned Qwen2.5-0.5B with supervised learning, then independently aligned it on HH-RLHF and UltraFeedback preferences. I also trained a SmolLM2 persona adapter. Both general DPO runs improved held-out preference metrics, but that improvement did not consistently carry into generation: HH DPO reached a 50.0\% tie-adjusted rate against SFT on Alpaca and 46.2\% on the HH bank; UltraFeedback reached 40.8\% and 38.3\%. The persona adapter separated all 22 validation pairs while leaving 38 of 40 greedy answers unchanged. The central finding is a gap between \emph{learning preference likelihoods} and \emph{producing better answers}.}

\section{Models, datasets, and experimental scope}
The completed project is \href{https://github.com/salehfarooq/cs5326-pa2-small-model-alignment}{github.com/salehfarooq/cs5326-pa2-small-model-alignment}. The general pipeline uses \model{Qwen/Qwen2.5-0.5B}: base $\rightarrow$ SFT $\rightarrow$ two independent DPO policies. Both DPO policies and their frozen references start from the same SFT checkpoint, so the HH and UltraFeedback (UF) tracks differ in preference data rather than initialization. The persona experiment uses \model{HuggingFaceTB/SmolLM2-360M-Instruct}, with its unmodified instruction model as baseline and frozen reference.

\section{Training objective and executed configuration}
\subsection{Response-only learning}
For instruction $x$ and response $y$, the causal sequence score is
\begin{equation}
\ell_\theta(y\mid x)=\sum_{t=1}^{T}m_t\log p_\theta(z_t\mid z_{<t}),
\label{eq:score}
\end{equation}
where $z$ is the tokenized prompt--response sequence and $m_t=1$ only for retained response tokens, including EOS when retained. The implementation shifts predictions and targets by one position; prompt and padding positions are masked. SFT minimizes response-token mean negative log-likelihood. DPO uses the \emph{sum} in Eq.~\eqref{eq:score}, rather than a length-normalized response score.

\Needspace{7\baselineskip}
For preferred and rejected responses $y_w,y_l$, define the reference-relative reward $r_\theta(x,y)=\beta[\ell_\theta(y\mid x)-\ell_{\rm ref}(y\mid x)]$. The custom DPO loss follows \cite{dpo}:
\begin{equation}
\mathcal{L}_{\rm DPO}
=-\mathbb{E}_{(x,y_w,y_l)}\log\sigma\!\left(r_\theta(x,y_w)-r_\theta(x,y_l)\right).
\label{eq:dpo}
\end{equation}
The reference stays frozen and is scored without gradients. Validation reports mean DPO loss, strict reward accuracy $\Pr(r_w>r_l)$, and mean margin $\mathbb{E}[r_w-r_l]$. Identical initial policy and reference yield loss $\log 2$, zero margin, and \term{0\% strict accuracy}, since tied rewards do not satisfy $r_w>r_l$.

SFT and general DPO use custom PyTorch loops. Persona uses TRL's \texttt{DPOTrainer} and PEFT LoRA~\cite{trl,peft}. Qwen training uses gradient checkpointing and disables the KV cache. During DPO, the policy runs on one T4 and the independent frozen reference on the second. The final 24-pair DPO accumulation window is normalized by its actual pair count; SFT accumulation is weighted by response-token count.

\subsection{Prompt and generation contracts}
Qwen uses the following literal template in training and evaluation, without applying its stored chat template:
\begin{center}
\fcolorbox{light}{light!35}{\parbox{.94\linewidth}{\small\ttfamily
Instruction:\textbackslash n\{instruction\}\textbackslash n\textbackslash nResponse:\textbackslash n}}
\end{center}
Persona uses SmolLM2's native chat template, including its default helpful-assistant system text. No Ramsay instruction is added by the caller. Matched evaluation is greedy: \texttt{do\_sample=False}, 256 new tokens, repetition penalty 1.1, and no n-gram block. Temperature and top-$p$ are inactive; no explicit length penalty is supplied. Qwen uses EOS/padding ID 151643. Each comparison preserves the complete instruction and uses identical decoding across models.

\section{Parameter choices and deviations}
\term{Memory-driven choices.} SFT microbatch 2 with accumulation 16 and DPO microbatch 1 with accumulation 32 both retain effective batch 32. The memory layout retains the guide's effective optimization batch.

\term{Decoding-driven choices.} An initial 4-gram block broke legitimate dictionary-counting code. Removing it restored executable counting functions in both base and SFT. Raising the repetition penalty from 1.05 to 1.1 subsequently stopped an observed UF development loop, but UF's planet-name length function still regressed. All final compared outputs were regenerated under 1.1/block 0. This was a documented tradeoff: improved local loop control with incomplete code preservation.

\term{Optimization choices.} General DPO keeps the guide's $\beta=0.1$, fixed LR $10^{-6}$, and one epoch. Weight decay 0 and validation every 50 updates are implementation choices. An earlier 200-update HH pilot improved some answers but failed a safety review. The full one-epoch runs were separate guide-recipe executions; the pilot did not establish an optimal setting.

\term{Persona capacity and coverage.} Rank 8, alpha 16, and query/value projections give 819,200 trainable parameters, a small adapter for 220 pairs. Zero dropout makes reference comparisons deterministic. LR $10^{-5}$ and one epoch limit optimization on that small dataset. Explicitly requesting 13 updates corrects partial-batch rounding in the pinned Trainer and completes one epoch. Although context is 1024, the longest formatted preference sequence is only 123 tokens, so training pairs are not truncated. The weak generated style shows that these conservative choices did not achieve the intended persona effect.

\section{Matched evaluation results}
\subsection{Blind DPO--SFT comparisons}
Generation persisted 2,100 responses: base on Alpaca, plus SFT and both DPO models on Alpaca and HH. All banks contain 300 answers with zero blanks. Four 300-pair files compare DPO against SFT with seed-42 A/B randomization and separate identity mappings. Local checks reconstruct the pairs byte for byte.

A separate Kaggle utility notebook judges the saved pairs with \model{google/gemini-3.6-flash} (SDK 0.6.1), using correctness, helpfulness, instruction following, formatting, and absence of hallucinations or unsafe content. The evaluator submits five pairs per request, waits at least five seconds between attempts, allows three attempts per batch, persists validated judgments after each batch, and supports resume. It reports zero unknown, unresolved-failure, and pending judgments. The recovered attempt journals record 250 request attempts for 240 initial batches: one HH/Alpaca retry and nine UF/Alpaca retries. Malformed or partial returns are validated by ID; valid judgments are retained, remaining IDs are retried, and unresolved failures are logged separately. All 1,200 judgments and the reported bootstrap intervals reproduce locally from the original saved records.

For DPO wins $W$, ties $T$, and losses $L$, the two rates are
\begin{equation}
\widehat p_{\rm tie}=\frac{W+T/2}{W+T+L},\qquad
\widehat p_{\rm decisive}=\frac{W}{W+L}.
\label{eq:rates}
\end{equation}
Both describe DPO relative to SFT. The tie-adjusted rate has parity at 50\% and is the primary comparison; unlike evaluation banks are reported separately.

The saved uncertainty calculation uses 2,000 bootstrap resamples and seed 42. HH resamples its 185 canonical instruction clusters instead of treating all 300 rows as independent. These intervals represent sampling variation in these comparisons, rather than judge bias or training-seed variability.

\subsection{Why might preference learning fail to improve generation?}
\term{Observed preference-data risks.} Complete-pair reviews found questionable chosen labels in both sources, including factual errors and mismatched refusals. Raw-source checks found no converter label swap. UF chosen responses are truncated in 3,987/15,000 training pairs, versus 28/15,000 for HH; the sampled mean chosen/rejected length ratios are 1.96 and 1.60. The response-summed DPO objective can therefore learn from noisy or unevenly retained comparisons. This is a plausible contributor, not an isolated causal explanation.

\term{Observed generation risks.} UF hits the response cap on 138/300 Alpaca and 163/300 HH answers, compared with SFT's 56 and 52 and HH's 41 and 34. Length limits alone do not imply poor quality. Manual inspection also confirms sustained repetition in final banks: repeated ``please'' in a landlord-message rewrite, hashtag repetition, and an HH emoji loop. The development decoder repair did not eliminate benchmark degeneration.

Together, these observations suggest that higher reference-relative likelihood separation is insufficient when preference labels, response coverage, and autoregressive behavior remain problematic. UF's worse blind scores are measured; data mismatch, over-optimization, and decoding sensitivity are hypotheses about their cause. The persona result is consistent with under-adaptation: small positive margins change pair ranking while rarely moving greedy decoding to a different answer. These runs do not identify which single adjustment would resolve either failure.

\section{Limitations, reproducibility, and conclusion}
All training uses one seed, and general evaluation uses one model judge. Exact-text exclusions do not rule out semantic overlap. The HH bank repeats instructions; the persona assessment has only 22 held-out preference pairs and 40 purposefully adversarial prompts. Decoder selection has a documented code-quality tradeoff. These limits constrain the size and generality of the quality claims.

\term{Reproducibility.} The project retains code, prepared splits, training metrics, checkpoint states and hashes, all matched outputs, blinded pairs and mappings, and the complete saved judge journals (Table~\ref{tab:evidence}). Its assembled code passed 381 offline tests, including all seven unchanged public adapter tests. Large weights remain in the private Kaggle outputs and were not rehashed locally during report preparation. Training does not resume optimizer state; generation and judging persist progress.

\term{Conclusion.} The strongest result is that learning the preference objective did not reliably improve generated quality. HH DPO shows no clear gain over SFT; UF DPO performs worse under the saved judge on both banks. Persona reaches perfect validation preference separation with little useful style transfer. SFT remains the stronger baseline against UF, while preference accuracy should be interpreted alongside matched generation, correctness, and safety rather than used as their substitute.
